Version 2: a redesigned academic portfolio with a form-based content editor, section-level Add/Edit controls, a full-image slideshow, and support for a shared visit counter. The portfolio pages need no WordPress installation, paid theme, or build command. The optional shared counter uses its own small database. The site uses ordinary HTML, CSS, and JavaScript.

New in this version

  • A continuous dark navy theme, subtle geometric detail, cyan accents, and a broader AI, intelligent systems, and engineering introduction. The first-page highlight box is removed.
  • Add/Edit controls in every section: use Manage content in the footer, or open index.html?manage=1. Opening the local file enables editing mode automatically. These controls open the relevant editor section; they do not let visitors publish changes.
  • Full-image gallery: uncropped photographs, captions below each image, previous/next arrows, thumbnails, swipe support, and a visible progress indicator. The default slide interval is six seconds. Reduced-motion preferences disable autoplay by default.
  • Shared visit counter: the complete counter service is included in counter-service/. It counts repeat visits. It needs to be deployed and connected once using the setup below; the website does not invent a number before setup.

3. Publish with GitHub Pages — no coding

Your CV lists tnirob30.github.io/resume/. If tnirob30 is still your GitHub username, use the steps below. If your username differs, replace it wherever shown.

  1. Sign in at github.com.
  2. Click + in the top bar, then New repository.
  3. Name the repository tnirob30.github.io — exactly your username followed by .github.io. Set it to Public, turn on Add README, and create the repository.
  4. Open the repository’s Code tab. Choose Add file → Upload files.
  5. On your computer, open the extracted portfolio folder. Drag the files inside it and the entire assets folder into the upload area. Upload the contents, not the enclosing folder and not the ZIP. At minimum, upload index.html, content.js, editor.html, START-HERE.html, and assets/.
  6. At the bottom, enter a message such as Add academic portfolio, choose to commit directly to main, and click Commit changes.
  7. Open Settings → Pages. Under Build and deployment, choose Deploy from a branch. Select main and /(root), then click Save.
  8. Wait for GitHub to publish. GitHub says this can take up to 10 minutes. Check the repository’s Actions tab for the Pages deployment result.
  9. Return to Settings → Pages and click Visit site. Your expected URL is https://tnirob30.github.io/. It becomes your new portfolio only after your upload and a successful deployment.
If that repository already exists: download a backup with Code → Download ZIP before replacing anything. To keep an existing root website, create a new public repository named research-portfolio instead. The same files work without changes; the expected URL becomes https://tnirob30.github.io/research-portfolio/. You can also update an existing resume repository after backing it up, preserving the URL in your CV.

A public repository works with GitHub Free. The site’s source files and uploaded CV will be publicly accessible. No payment or custom domain is required for the github.io address.

Optional: an empty .nojekyll file is included to disable Jekyll processing. Windows may hide it. If you cannot upload it, use Add file → Create new file, name it .nojekyll, and commit. The supplied website does not rely on Jekyll features.

4. Update anything using the visual editor

  1. Open the most recent copy of editor.html. You can open it locally, or at your live site followed by /editor.html, for example https://tnirob30.github.io/editor.html.
  2. Select a content section from the menu. Edit the labeled fields. Use Add entry, ↑, ↓, or Remove to manage entries.
  3. Click Preview. Use Narrow view to preview the phone layout. Close the preview to continue editing.
  4. Click Download content.js. If your browser saves content (1).js, rename it to content.js.
  5. For a local update, replace the existing content.js in your extracted portfolio folder, then reload index.html.
  6. For the live update, open your GitHub repository → Add file → Upload files. Upload the new content.js into the repository root, replacing the existing file. Commit with a message such as Update publications and projects.
  7. Wait for the Pages deployment to finish, then refresh the website. On Windows, use Ctrl + F5 if the old version remains visible.
How this differs from WordPress: the editor saves a downloadable file. It does not log in to GitHub, modify the repository, or publish automatically. Opening the editor does not grant anyone access to your account. Only someone with repository write access can upload changes. Do not put passwords or access tokens in any website file.

Save draft stores the current draft in the browser on that device. It is not a backup or an online save. Browser storage can be unavailable or fill up with photos; in that case download content.js. Load draft restores a deliberately saved draft. Import content.js lets you load a downloaded content file on another device without typing any code.

To avoid starting with an old copy, download the latest repository ZIP before an editing session, or open the live editor after refreshing it. If multiple people edit, agree on who will publish the next version.

5. Add a portrait, project images, and gallery photos

  1. For your portrait, open Profile & contact → Portrait → Choose image.
  2. For a project screenshot, open Projects, find the project, and use Project image → Choose image.
  3. For a gallery photo, select Photo gallery → Add entry. Add a caption, event/date/location, photograph, and a short image description.
  4. Click Preview. Gallery photos open in a larger view when selected. Images have keyboard-accessible controls; Escape closes the enlarged view.
  5. Download and upload content.js as described above. You do not have to upload the original images separately when using Choose image.

The editor resizes uploaded images and embeds them in the content file. This makes small galleries easy to maintain. JPG, PNG, WebP, and GIF are accepted; uploaded GIFs become still images. A portrait is resized to at most 1,000 pixels on its longest side, other images to 2,400 pixels. This is intended for web display, not an archive of original images.

For a large gallery, use separate files: upload photographs into assets/photos/ and type paths such as assets/photos/becithcon-2026.jpg in the image field. Keep filenames simple and match capitalization. Then upload content.js. Aim for a small content file; the editor prevents downloads above 20 MB. You can hide an empty gallery under Display settings.

6. Update project links and certifications

Project posts: open the exact LinkedIn post, use its share/menu option to copy the post link, and paste it into Exact LinkedIn project post URL. A profile URL is not a project post. You can also add a GitHub code URL and live demo URL. Blank fields produce no buttons.

Certificates: under Certifications, edit the course, issuer, date, and details. Add the official credential verification URL, a public certificate PDF URL, or use Certificate scan → Choose image. For a PDF stored in the repository, upload it under assets and enter a path such as assets/tici-certificate.pdf. Certificate scans open in a modal; credential links open in another tab.

Publication status: the published count includes only records whose status is Published. An accepted or submitted manuscript remains in the manuscript group until you deliberately change its status to Published. Always preserve author order and add the actual DOI or publisher link.

9. Troubleshooting and backup

The page is blankConfirm content.js is present, correctly named, and JavaScript is enabled. Use a freshly exported file from the editor. Do not paste JavaScript into the filename field on GitHub.

11. Activate the shared visit counter

Your public portfolio stays on GitHub Pages. GitHub Pages does not run the database service needed for a shared counter. The supplied service uses a Cloudflare Worker and D1 database; setup is performed in your own account.

  1. Create a D1 database named portfolio-visits in Cloudflare. Open its Console and run the contents of counter-service/schema.sql.
  2. Create a Worker. In its code editor, replace the default code with counter-service/worker.js and deploy.
  3. In the Worker’s Bindings tab, add your D1 database using the exact binding name DB.
  4. Add a text variable named ALLOWED_ORIGINS with https://tnirob30.github.io, or your actual GitHub/custom-domain origin. Do not include a repository path or trailing slash.
  5. Copy the Worker’s actual HTTPS URL. Opening it should display a JSON count. A direct GET reads the total without increasing it.
  6. In the portfolio editor, open Display settings & counter and paste that URL into Visit counter endpoint. Download content.js and upload it to GitHub.
  7. Visit the public website in visitor mode. Reload it to confirm the total increases. Local files, editor previews, and editing mode do not count.

The counter counts page visits, including repeats, rather than unique people. Network failures and bots can affect totals. The database stores only the total; it does not store visitor identifiers. Cloudflare receives normal connection metadata. The Free plan has usage limits. For fuller instructions and troubleshooting, open counter-service/README.md. The counter has not been deployed for you.
